### 判定依据

1. **「同角色不同档」零命中**：逐一核对多用途档（11/12/13/15）的使用位置，
   均为「同一层级语义在不同组件」而非「同一元素两种写法」；
2. **半像素家族**（10.5/11.5/12.5/14.5，25 处）由《设计规范-排版.md》声明为
   有意的视觉微调——本轮审计未发现反例，维持保留；
3. **单次出现 ≠ 不一致**：12 个单次值里，8 个是唯一职责的组件字号
   （护照名 40 / 灯箱按钮 20 / 页脚大数字 22……），它们没有「相邻档同角色」
   的合并对象，合并只会制造信息丢失；
4. 响应式配对（8.5↔9.5、24↔28、两个 clamp）是断点设计的组成部分。

## 四、被否决的候选（评估过，证据在案）

**`.stFoot` 9px → 9.5px**（与 9.5 家族对齐）：

- 否决理由 ①：`.stFoot` 为 `white-space:nowrap` 页脚注脚（letter-spacing .04em），
  增大字号直接加宽整行，**存在溢出风险**，收益（0.5px）肉眼不可辨；
- 否决理由 ②：违反「一次只动一档 + 截图对比后再动」的自定纪律——为不可辨
  收益动第一档，会打开潘多拉盒子；
- 评估证据：沙箱变体（v31 + 仅此一处改动）已构建并截图
  （`E:\tmp\shotcmp\v31-stfoot95-*.png`，临时产物，不入库）。

## 五、迭代 2 实施项：字体栈覆盖面缺口（v32）

审计同时发现比字号更要紧的真不一致——**v31 只兜底了 CSS，canvas 与独立页没有**：

| 位置 | v31 状态 | 问题 |
|---|---|---|
| canvas 导出图（护照 `FT` / 分享卡 `_FT` 常量 + 17 处字面量，共 44 处赋值） | 裸栈 `"PingFang SC","Microsoft YaHei"` | 装有 HarmonyOS/MiSans 的 Windows 与 Linux 上，**页面与导出图字体不一致**（导出图跌回默认黑体） |
| `gallery/index.html` | 裸栈 + system-ui | 同上（影廊索引页） |
| `404.html` | 裸栈 | 同上 |

**修复（v32，`tools/make_v32_baseline.py`，5 条 U2 补丁）**：全部在
Microsoft YaHei **之后**追加 HarmonyOS Sans SC / MiSans / 思源黑体 /
Noto Sans CJK SC——与 v31 的 CSS 同构，macOS/Windows 首选不变 → 零观感回归，
离线红线不破（纯系统字体）。其中 `FT`/`_FT` 两个常量的锚点带前导空格边界
（`FT=` 是 `_FT=` 的子串，次数断言首次运行即拦下此误）。
