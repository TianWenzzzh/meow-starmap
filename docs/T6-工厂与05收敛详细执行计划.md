## 1. 目标与非目标

**目标（收敛完成的定义）**

1. 三仓共享同一模板血脉：**工厂 `app/templates/starmap_v29.html` 为上游真相**，
   开放仓库模板与 05 外发 HTML 均由同一套确定性规则生成，字节级可往返。
2. 工厂新学校在线生成即享 v28 全特性 + 照片懒加载（首屏 ≤0.6MB）+ F11
   主题色/校徽/自定义分区（空值=默认，中北产物字节不变）。
3. 工厂既有 **730 条测试不降级**；新增的等价性、懒加载、XSS 测试进双 OS CI；
   full76 在 Windows 满血验收通过。
4. 05 正式版升级到 v2.9 懒加载产物，与开放仓库 `nuc/` 托管版同源；
   中北特有人工文案（指南面板三段、归并摘要口吻等）一处不丢。
5. 结束代码分叉：开放仓库 build.py 改为**消费**工厂上游渲染器（vendor 快照），
   不再各自维护一套注入逻辑。

**非目标**：不改工厂 FastAPI 的 zip 限额/锁/并发安全层；不做工厂在线服务部署
（那是人类运维动作）；不迁移工厂测试框架；不重写 717 行旧模板（保留一个版本周期后删）。

## 3. 目标架构：v29 模板（v28-lazy + F11 三增量，空值零差异）

### 3.1 token 合并总表（在开放仓库 v28 上新增，而非在工厂侧拼装）

| F11 增量 | v29 锚点（拟） | 默认注入 | 工厂来源 |
|---|---|---|---|
| `__THEME_CSS__` | `<head>` 主样式块之后独占一行（新整段规则，带次数断言） | 空串（v28 字节不变） | `theme.css_block(theme)`，无自定义=空 |
| `__LOGO_HTML__` | 两处：极光开场品牌行 + 主界面顶栏品牌位 | 空串（v28 无校徽位，空串即原样） | `injector.logo_tag(logo_src)`，白名单不放松 |
| `__ZONES__` → 并入 `__AREAS_BLOCK__/__AREA_KEYS_BLOCK__` | v28 星域数据块 | 由名册出没区 `derive_areas/assign_anchors`（=现行） | 自定义分区 JSON 命中时覆盖锚点，缺省推导 |

**关键原则**：三个新 token 全部「空值=v28 逐字节相同」，中北 76 只产物在默认
路径下与 v1.1.0 字节一致（靠现有往返测试强制）。logo 空串时模板里不得出现碎
`<img>`（沿用工厂「整标签生成」模式）。

### 3.2 渲染器归属反转（结束 vendor 倒置）

- 现状：开放仓库 build.py vendor 了工厂 injector/image_proc/csv_loader，之后
  各自加了懒加载、名册校验、零底图、富文案默认值 → 分叉。
- 目标：把开放仓库 build.py 中**与 HTTP/FastAPI 无关的纯渲染层**
  （规则值生成、lazy/eager 分片、CATS/CALIB/AREAS/星宿主文案默认值、富 meta）
  抽成单文件 `starmap_render.py` 落进工厂，成为唯一上游；
  开放仓库 build.py 与工厂 injector 都只做「数据装配 → 调渲染器」。
- 契约：渲染器输入 dataclass（school/product/en/meta/rows/override/calib/
  areas/consts/stars/theme/logo/zones/photo_loading…），输出
  `(html, groups, key_chunk)`；不碰文件系统以外的 IO、不 import fastapi。

## 4. 分阶段施工（每阶段独立 PR/提交，出门证据不齐不进下一阶段）

### F0 · 门禁与基线（人类 + 机器，0.5 天）

- **出门证据**：两仓分支就位、G1 授权留痕、工厂绿灯基线数字归档。

### F1 · 开放仓库先行：v28 → v29 模板（机器，0.5 天）

在 **16 仓库**先做（golden 机器最完备，改动最便宜）：

1. `tools/make_v28_baseline.py` 演进（或新建 `make_v29_baseline.py`，v28 快照保留）：
   追加 THEME_CSS / LOGO_HTML×2 三个补丁规则；ZONES 不新增模板 token
   （在渲染层并入 AREAS）。
2. fixtures 增 `v29_baseline_lazy.html`、规则文件 v29；往返测试加 V29 类
   （默认空值路径必须与 v28 nuc 产物**字节一致**——用强断言锁死）。
3. build.py 的 `build_meta.json` 接受可选 `theme/logo/zones` 并透传渲染器
   （开放仓库 CLI 不暴露校徽上传，只保证数据通道存在且默认空）。
4. 全量 52+N 测试、双冒烟绿；发开放仓库 **v1.2.0-rc**（不切 latest）。
- **出门证据**：V29 往返绿、默认路径 nuc 产物 sha 与 v1.1.0 相同（除版本注入外）、
  远端双 job 绿。

### F2 · 工厂引入 v29 模板与共享渲染器（并存，不切换；1 天）

1. `app/templates/starmap_v29.html` ← 16 仓库 v29 模板（一字不差，附来源哈希注释）；
   旧 717 行 `starmap.html` 原地保留。
2. 新增 `app/starmap_render.py`：从 16 仓库 build.py 抽取的纯渲染层（含懒加载
   引导/加载器补丁、富文案默认值、lazy/eager 分片），头部注明 MIT 同源。
3. injector 增加 `render_starmap_v29(...)`：把工厂 CatRow/Theme/logo/zones
   适配成渲染器 dataclass；**旧 `render_starmap` 一行不删**，由 `--engine v1|v29`
   /配置选择，默认仍 v1。
4. XSS 三套转义在适配层强制复用（校名→`_js_str`、校徽→白名单、主题 CSS
   只允许来自服务端 Theme 规范化结果，不吃用户原始 CSS 文本）。
- **出门证据**：工厂全量测试仍绿（新文件不挂默认路径）；新增渲染器单测
  （demo2 数据出 v29 HTML、无残留 token、空 F11 三值时无 logo img/无额外 CSS）。

### F3 · 两种产物形态接入懒加载（0.5 天）

- `inline`（base64 分片）：采用 v29 的 **00 底图关键片 + 01..N 猫片懒加载**，
  packager 按新 `groups/key_chunk` 落盘并写 __PM 清单；在线生成 zip 首屏同样变小。
- `relative`（原始 jpg）：`__PHOTO_BOOT=null`，加载器自动退化为
  `Promise.resolve(PH(p))`，浏览器对 `<img>` 原生逐图加载——**不做分片**。
  用测试锁死两种形态在 file:// 下都可用（沿用 16 仓库 T0 spike 结论与脚本）。
- 新增 `photo_loading` 服务端参数透传（默认 lazy；保留 eager 出口）。
- **出门证据**：两种形态产物在 http + file:// 双协议浏览器冒烟通过；
  inline 初始仅 00 片的网络断言（移植 ci_browser_smoke.py 思路）。

### F4 · 测试与 CI 加固（0.5–1 天）

1. **不降级红线**：ubuntu+windows 矩阵上现有 576 函数 / ~730 条全绿；
   任何旧用例红先修适配，不许删用例。
2. 新增：v29 引擎的 CATS/CALIB/分片字节等价（移植 16 仓库 test_build_nuc 断言）、
   名册校验（空/重复 ID 拒绝，工厂 validate 层也要拦）、模板残留 token、
   v1/v29 双引擎同数据输出一致性（共有的猫字段全等）。
3. 浏览器冒烟进 CI：**仅 ubuntu job**（windows 装 Chromium 成本高，矩阵里
   加 `if: runner.os=='Linux'` 一步），跑 demo2 产物的初始片数/灯箱解码/file://。
4. test_ci.py 增补：工作流必须跑 v29 引擎单测与 linux 浏览器冒烟，防后人摘步骤。
- **出门证据**：两 OS 全绿的 run 链接；测试条数只增不减的数字对比。
