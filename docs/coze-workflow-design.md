# Coze 工作流设计稿：上传名册+照片 → 返回星图 HTML

> 对应规划报告 §5.4「扣子/Coze 工作流版生成器：最符合国内学生习惯的分发形态，
> 优先于买服务器」。本文是设计稿与上架申请素材，**未实际上架**。
> 决策依据：单人运营公网服务是街猫式陷阱；Coze 承担分发与算力，我们只维护
> 构建内核（与 meow-starmap build.py 同源的确定性构建，无状态、可重放）。

## 一、工作流形态

```
用户上传 zip（名册.csv + photos/*.jpg + map/*.jpg）
  │
  ▼
[节点1 输入校验]   zip ≤100MB；条目 ≤2000；无嵌套 zip；CSV 是 UTF-8/GB18030 可解码
  │
  ▼
[节点2 代码运行]   调构建内核（示例校 demo 数据演示；正式上架需 Coze 侧
  │               提供持久化代码环境或走"插件"封装 build.py——见 §四）
  ▼
[节点3 产物打包]   <校名>喵星图.html + assets/photo-data-*.js → zip 返回
  │
  ▼
[节点4 回复卡片]   产物链接 + 双击即开说明 + 数据许可声明 + 仓库二维码
```

## 二、与本项目边界

| 项 | 决策 |
|---|---|
| 构建内核 | 与 16 仓 build.py 同源（渲染真相 = 工厂 starmap_render），确定性、字节级可测试 |
| 照片压缩 | 保真直通策略（合格 JPEG 原字节嵌入），上传侧不做二次压损 |
| 人工数据 | cats_override / calib / areas 等可选文件全支持（数据包约定不变） |
| 用户数据留存 | **不留存**：工作流结束即弃；隐私与照片权利归用户 |
| 滥用限额 | 单用户 5 次/日；单 zip ≤100MB；产物含水印角标（Coze 平台自身机制） |

## 三、上架前验收（自建试用环境先跑通）

1. 示例校 demo 包 → 产物与本地构建**字节一致**
2. 恶意文件名（`../`、全角空格、`</script>` 校名）→ 工作流拒绝且信息可读
3. 断网场景文案：产物是离线单页，双击即开，无需回访平台
4. 免费额度跑满 50 次构建无超时（估算：2 猫 demo ≈8s，76 猫 nuc ≈45s）

## 四、两条落地路径（按平台能力选）

- **A. 插件封装**：把 build.py 封装成 Coze 插件（服务端跑在我们控制的
  免费 runtime，如 Hugging Face Space / Render free tier——这不算"买服务器"，
  是平台免费层）；工作流只做编排。
- **B. 纯工作流**：节点2 用 Coze 代码节点内嵌精简构建逻辑（受限于代码节点
  无文件系统的约束时，降级为「返回构建命令 + 教程链接」的半自动形态）。

## 五、上架申请要点（给人类执行时用）

- 类目：教育/校园工具；名称建议「喵星图 · 校园猫咪星图生成器」
- 描述三件套：能做什么 / 数据许可（CC BY-NC-SA，权利归用户）/ 开源地址
- 依赖的开源仓库：meow-starmap（模板+构建）+ catgalaxy-factory（渲染上游）
- 人工动作：上架、实名、额度配置都是人类操作；本设计稿只备料
