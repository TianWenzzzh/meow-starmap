### 对规划措辞的一处事实修正

规划文档把「冬季初雪」列为 v2.7 特性。实测模板内 `snow/season/winter/flake`
计数全为 0——**「初雪」是中北 76 只猫之一的名字**（纯白小猫，见 CATS 小传），
不存在季节特效代码。收敛时不要凭空补这个功能。

## 2. 新学校今天用工厂会失去什么

工厂在线生成器仍能产出**可玩的基础星图**（星点/档案卡/筛选/寻猫），
但相比 v2.7 开放模板会少：极光开场与品牌仪式感、影廊灯箱、本命猫测试、
喵星护照与跨设备进度码、带照片与署名的分享卡、全链路原创署名。
这些恰好是中北版传播力的主要来源（分享卡与灯箱是短视频的核心画面）。

同时工厂有而开放模板没有的：F11 的**一键换主题色、校徽注入、自定义分区 ZONES**
——这三样对「多校快速换皮」很有价值，收敛时必须作为增量保留，不能被覆盖丢失。

## 3. 收敛目标形态

工厂与开放模板共用同一份模板基线（v2.7 全特性），差异只通过 **token 配置**表达：

```
app/templates/starmap.html        ← 以开放模板 3320 行为新基线
tokens:
  基线 52 规则（CATS/CALIB/AREAS/…，开放模板已固化）
  增量（来自工厂 F11）：
    __THEME_CSS__    主题色覆盖（无自定义时注入空串，渲染零差异）
    __LOGO_HTML__    校徽/品牌位 HTML（转义后注入；无校徽时注入默认品牌块）
    __ZONES__        自定义分区（缺省时由构建器按出没区域自动推导，等同现行为）
```

关键原则：**新 token 必须有「空值=v2.7 原样」的默认注入**，
使中北数据在新基线下的产物仍能通过字节级/语义级往返。

## 5. 风险与对策

- **风险**：v2.7 模板体量大（3320 行），工厂页面注入逻辑按 717 行结构编写，
  可能有选择器/变量名耦合 → 对策：先在测试里 grep/断言关键 id 与全局变量契约，
  再动注入器；
- **风险**：F11 校徽位是 HTML 注入，XSS 面扩大 → 对策：强制走工厂现有
  `injector.py` 的 `_html/_js_str/_js` 三套转义，新增测试喂恶意校名/校徽串；
- **风险**：在线服务端内存/体积（照片 base64 + 大模板）→ 对策：模板不随
  请求重复解析，启动期缓存；产物体积与离线版一致（中北 8.27MB 数据量级已验证）。
