# 照片分片懒加载改造方案（模板基线 v2.7 → v2.8-lazy）

> 2026-09-16 设计书，只写方案不改代码。目标：把 /nuc/ 首屏从 eager 全量
> **11 MB / 9 分片**降到「HTML + 底图 ≈ 0.5 MB 起步、按交互取片」，
> 同时保住「双击 HTML 全离线可用」这一产品红线。
> 本方案所有结论均基于对模板 3320 行与 build.py 758 行的逐点核实（行号为当前基线）。

## 1. 现状机制（事实，非推测）

- 构建器 [build.py](../tools/build.py) 把所有照片（含底图）按 ≤1.5MB 分片，
  在 HTML 里渲染 **9 个立即加载的 script 标签**（`tools/build.py:718-723`），
  分片文件是经典脚本：`window.__PHOTOS={…}; __PHOTOS["k"]="data:image/jpeg;base64,…";`
- 模板 [starmap.html](../template/starmap.html) 第 950 行：
  `__PHOTO_SCRIPTS__<script>function PH(p){…}</script>`；
  `PH()` 是**同步**查表，查不到回退原路径。
- 底图也在 `__PHOTOS` 里，且星图画布**启动即依赖**：
  `mapImg.src = PH(MAP_SRC)`（模板 974-976）。
- 猫照片的 10 个消费点（全部假设数据已在内存）：

| # | 位置 | 形态 | 改造敏感度 |
|---|---|---|---|
| 1 | 976 `mapImg` 底图 | 直接 src | **必须保持 eager** |
| 2 | 1996 档案卡 `#cardImg` | 直接 src，已有 loading 占位/onerror | 中（天然可异步） |
| 3 | 2166-2169 分享卡 makePoster | `new Image` onload，3.5s 超时 | 低（回调式） |
| 4 | 2417 搜索结果 innerHTML | `<img src>` 字符串 | 高（批量，需后置绑定） |
| 5 | 2619 统计/影廊列表 innerHTML | 同上 | 高 |
| 6 | 2640-2667 星尘变身 startMorph | `new Image`→canvas 取像素 | 低（已有污染降级） |
| 7 | 2821 本命猫结果 innerHTML | `<img class=sqRImg>` | 高（单点，易绑） |
| 8 | 2882-2883 本命卡 drawShareCard | `new Image` onload | 低 |
| 9 | 2935-2938 表情包工坊 | `new Image` onload | 低 |
| 10 | 3234-3237 影廊灯箱 / 3300 悬停 peek | `new Image` / 直接 src | 中（翻页要预取） |

- 模板被字节级往返锁死在 v2.7 golden 基线（`tests/fixtures/v27_baseline.html`
  + `nuc_literals.json` 52 条规则，`photo_scripts` 是其中一条整块规则）。
  改模板 = 模板基线升级，必须同步规则凭据与 golden（见 §6）。
- 上游工厂 injector 的分片逻辑是本仓库 `chunk_plan/chunk_text` 的来源（MIT vendor），
  收敛路线见 [模板分叉与工厂收敛计划.md](模板分叉与工厂收敛计划.md)。

## 2. 目标 / 非目标 / 指标

**目标**

1. 首屏（页面加载 → 可点「入夜寻喵」交互）只取 HTML + 1 个底图关键片；
   猫照片在首次需要某只猫时才下载其所在分片。
2. **file:// 双击离线场景行为不退步**（关键约束，决定技术选型只能用经典脚本注入，
   不能用 fetch / ES module / dynamic import——后两者在 file:// 下被 CORS 拦）。
3. 灯箱翻页、档案卡、canvas 出图（海报/变身/本命卡/表情包）全部照常工作；
   加载中有与现有 `.loading` 星座徽记一致的视觉，不出现破图图标。
4. 提供 `--eager-photos` 构建开关产出旧行为的「整包分发版」（U盘/群文件场景）。

**非目标**：不做单猫单文件请求（75 请求无收益）；不重写 v2.7 UI；
不处理工厂在线服务端（留待收敛里程碑反向移植）。

**量化验收**（Playwright 网络计数，写进 CI 冒烟）

| 指标 | 现在 | 目标 |
|---|---|---|
| 初始文档+图片传输量（/nuc/） | ≈11.4 MB | ≤0.6 MB（HTML 248KB + 底图片≈192KB + 清单≈8KB） |
| 初始加载的 photo-data 分片数 | 9 | 1（仅 00 底图片） |
| 首次开卡/灯箱新增下载 | 0（已全载） | 恰好 1 片，≤1.5 MB |
| 灯箱连翻 10 张最坏新增片数 | 0 | ≤3（邻近预取生效） |
| 功能/视觉回归 | — | 现有 32 测试 + 浏览器冒烟全绿，0 pageerror |

## 3. 架构设计

### 3.1 分片布局：关键片 + 懒片

```
assets/
  photo-data-00.js   # 关键片：仅底图（≈62KB 示例 / ≈192KB 中北），保持 eager <script>
  photo-data-01.js … # 猫照片片，按现有 chunk_plan ≤1.5MB，全部懒加载
```

改动只在构建器的分组步骤：先把底图单独切出为 00，猫照片沿用 `chunk_plan`
顺序编号 01..N。**分片文件内容格式不变**（仍是 window.__PHOTOS 赋值），
因此现有 76 键 sha256/line_sha256 清单测试天然继续成立。

### 3.2 内联清单与加载器（模板永久代码，替换 950 行区域）

构建器在 `__PHOTO_SCRIPTS__` 处注入：① 00 片 eager 标签；② 内联清单
`__PHOTO_MANIFEST__`（`{键: 片号}`，76 条约 4-8KB）。其后是模板自带的加载器
（v2.8 永久代码，不走 token）：

```js
function PH(p){var k=String(p||"").split("/").pop();return (window.__PHOTOS&&__PHOTOS[k])||p}
const __PM = { n: <N>, m: <manifest>, jobs: {}, pend: {} };
function __chunkOf(p){ return __PM.m[String(p||"").split("/").pop"]; }
function __ensureChunk(i){
  if(__PM.jobs[i]) return __PM.jobs[i];
  __PM.jobs[i] = new Promise((res,rej)=>{
    const s=document.createElement("script");
    s.src="assets/photo-data-"+String(i).padStart(2,"0")+".js";
    s.onload=()=>{ __flush(i); res(); };
    s.onerror=()=>{ delete __PM.jobs[i]; rej(new Error("photo chunk "+i)); };
    document.head.appendChild(s);
  });
  return __PM.jobs[i];
}
async function __ensurePhoto(p){
  const k=String(p||"").split("/").pop();
  if(window.__PHOTOS && __PHOTOS[k]) return __PHOTOS[k];
  const i=__PM.m[k]; if(i==null) return p;          // 外链/无照片：直接回退
  try{ await __ensureChunk(i); }catch(e){ throw e; }
  return (window.__PHOTOS && __PHOTOS[k]) || p;
}
function __whenPhoto(p, fn){            // 供 innerHTML 列表后置绑定
  const k=String(p||"").split("/").pop();
  if(window.__PHOTOS && __PHOTOS[k]) fn(__PHOTOS[k]);
  else { (__PM.pend[k] ||= []).push(fn);
    __ensureChunk(__PM.m[k]).catch(()=>toast("一张照片分片没加载出来 · 检查网络或用整包版")); }
}
function __flush(i){                    // 片到达：唤醒等待者
  for(const k of Object.keys(__PM.m)){
    if(__PM.m[k]!==i || !__PHOTOS[k]) continue;
    const q=__PM.pend[k]; if(q){ delete __PM.pend[k]; q.forEach(fn=>fn(__PHOTOS[k])); }
  }
}
const __PH_STAR = "data:image/svg+xml;charset=utf-8,"+encodeURIComponent(
  '<svg xmlns="http://www.w3.org/2000/svg" width="408" height="264">'+ /* 复用现有星夜占位 */ '</svg>');
function __bindLazy(root){              // 容器内所有 data-pkey 图片统一绑定
  root.querySelectorAll("img[data-pkey]").forEach(img=>{
    if(img.dataset.bound) return; img.dataset.bound="1";
    const k=img.dataset.pkey;
    if(__PHOTOS[k]){ img.src=__PHOTOS[k]; return; }
    img.src=__PH_STAR;
    __whenPhoto(k, url=>{ img.src=url; });
  });
}
```

要点：Promise 去重（同片只插一次）、失败可重试（删 job）、`PH()` 同步签名不变
（底图已 eager，不受影响）、占位复用档案卡现有星夜 SVG 视觉。

### 3.3 十个消费点改造表

| # | 改法 |
|---|---|
| 1 底图 | 不改代码；构建器保证它在 00 关键片且保留 eager 标签 |
| 2 档案卡 | 保留占位与 onerror；ensure 回调带**开卡身份校验**（见 §3.3.1）；缓存直出分支保留 |
| 3 海报 | ensure 后赋值，3.5s 超时与失败降级逻辑不动；面板已关则丢弃结果 |
| 4 搜索 / 5 统计列表 | innerHTML 里把 `src="'+photoSrc(c)+'"` 改为 `data-pkey="<basename>"`（无 src），渲染后 `__bindLazy(容器)` |
| 6 星尘变身 | 同 3，ensure 后再赋值；canvas 污染/空点降级不动 |
| 7 本命结果 | innerHTML 后对 `.sqRImg` 单点 `__whenPhoto` 绑定 |
| 8 本命卡 / 9 表情包 | 同 3 |
| 10 灯箱 | `lbRender` 改 ensure 赋值并**复用现有 `GALLERY[lbIdx]===c` 身份校验**；打开灯箱后 requestIdleCallback 预取 GALLERY 前后各 1 只所在片；peek 同样 ensure 但悬停回调要核 `hovered===peekCat`。尊重 `navigator.connection.saveData` 时不预取 |

统计面板打开时允许顺序预取全部片（用户主动要看 76 宫格，属显式意图）。

#### 3.3.1 异步竞态防护（同步→异步后新出现，必须统一处理）

照片从"查表即得"变 Promise 后，旧代码的同步假设全部失效，三类竞态逐点防：

1. **快速切换主体**（档案卡连开两只、灯箱连翻、悬停快速划过）：
   回调落地前必须核对"当前主体还是不是发起时那个"，模式统一参照灯箱已有的
   `if(lbOpen&&GALLERY[lbIdx]===c)`：
   - 档案卡：`.then(u=>{ if(selected!==c) return; img.src=u; })`，
     onerror/onload 同样先判身份，避免 A 猫的加载失败 toast 盖到 B 卡上；
   - 悬停 peek：`.then` 内核对 `hovered===peekCat && peek.classList.contains("on")`；
   - 海报/变身/本命卡/表情包：回调内核对对应面板仍 open 且对象未换
     （如 `MEME.cat===selected` 模式，表情包现有代码已是这个写法，照抄）。
2. **列表重渲染**（搜索面板每次输入都重建 innerHTML）：`__bindLazy` 已用
   `dataset.bound` 幂等；旧 img 随 DOM 丢弃，其 `__whenPhoto` 回调还会触发，
   回调内先判 `img.isConnected`（已脱离文档就只丢弃不赋值），避免无谓解码/回流。
3. **同一只猫多消费者**（卡与灯廊同时要同一键）：由 `__ensureChunk` 的 Promise
   去重与 `__flush` 多订阅者唤醒天然覆盖，不加额外锁；但严禁在回调里改全局
   `selected`/`lbIdx`，只允许写各自捕获的局部节点。

这些身份校验必须进 T3 的逐点验收清单（快速连开 5 张卡、灯箱连翻、悬停扫过 10 星，
DOM 最终状态与所点对象一致，无串图/无残留 toast）。

### 3.4 构建开关

- 默认：懒加载布局（Pages 与新学校受益）。
- `--eager-photos`（或 build_meta `"photo_loading":"eager"`）：
  渲染全部 `<script>` 标签、不注入清单/加载器（模板里加载器代码对无清单环境
  必须自检 no-op，保证同一模板支持两种产物），产出旧版整包。
- 学校 README/PR 指南注明：在线部署用默认；群文件/U 盘整包分发可选 eager。

## 4. file:// 可行性 Spike（T0，先于一切编码）

用 Playwright 以 `file://` 打开一个临时产物（非 http server）：

1. 初始只有 00 片；点档案卡 → 断言 `#cardImg.naturalWidth>0`（证明 file:// 下
   动态注入经典 script 可读同目录 js）；
2. 开影廊翻页 3 次 → 对应片到达、照片解码；
3. Chrome/Edge 预期通过；若任一主流浏览器 file:// 拒绝注入：
   **默认策略反转**——懒加载仅在检测到 http(s) 协议时启用，file:// 构建保持 eager；
   两种引导在构建期二选一，不把不确定性带进运行时。
   该 spike 结论必须先落进本文档再开工。

## 5. 对 build.py 的改动清单

1. 分组：`critical=[map_file]` 先出 00；`chunk_plan(猫照片)` 出 01..N；
   返回 `(groups, key→idx)` 供清单使用（`tools/build.py:718-723, 769-772`）。
2. 新渲染函数 `render_photo_bootstrap(groups, key_chunk, eager: bool)`：
   eager=True 输出旧 tags；False 输出 00 标签 + `<script>const __PM=…</script>`。
   替换 photo_scripts 规则的 value（规则本身与 token 名不变，减少 golden 扰动面）。
3. argparse 加 `--eager-photos`；meta 读取 `photo_loading`。
4. 分片文件内容函数 `chunk_text` 不动 → 76 键双 sha 清单测试继续绿；
   但「9 分片」相关断言改为「00 + 9」并新增「初始页只引用 00」断言。

## 6. 模板基线与 golden 策略（最关键的工程决策）

当前模板与 05 仓库 v2.7 做死字节往返；本项目红线规定 **05 仓库本阶段只读**。
两条路线：

- **路线 A（推荐）：模板在本仓库独立演进为 v2.8-lazy。**
  1. 保留 `v27_baseline.html` 与现有 9 条往返用例（历史回归，标记 v2.7）；
  2. 新增 `tests/fixtures/v28_baseline_lazy.html`：由一次性脚本
     `tools/make_v28_baseline.py` 对 v27 基线应用**本方案 §3 的确定性补丁**生成
     （脚本入库并可重跑，杜绝手改 golden），新增 v28 往返用例；
  3. `nuc_literals.json` 升级为 v28 规则集：`photo_scripts` 的 old/new 更新，
     新增加载器永久代码所在区域的规则与次数断言；旧规则文件留存
     `nuc_literals.v27.json` 供历史用例；
  4. 提取器 `extract_template.py` 标注「v2.7 历史提取器」，v2.8 模板真相源
     改为本仓库 + make_v28_baseline 补丁脚本；
  5. 待[工厂收敛](模板分叉与工厂收敛计划.md)里程碑，把 v2.8-lazy 模板反向并入
     工厂 injector（其 chunk_plan 同源，移植 §3.1-3.2 即可）与 05 正式版，
     届时两边重新共享基线。
- 路线 B：等 05 先改 v2.8 再提取。需人工解除 05 只读红线，周期不可控，不推荐。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| file:// 禁止动态 script（未证实） | 双击离线场景失效 | T0 spike；失败则运行时/构建期协议分流，eager 兜底 |

## 10. 一句话结论
